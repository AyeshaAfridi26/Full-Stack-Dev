Connecting JavaScript to HTML

There are three ways to get JS running on a page.

1. Inline — directly on an element

An on* attribute (like onclick) runs a snippet of JS when that event fires. Fine for a quick test, but mixes JS into HTML — avoid it in real projects.

(waiting for click...)

2. Internal — a <script> tag in the HTML file

JS written between <script> tags, usually placed right before </body> so the HTML above it has already loaded. This is what every demo on this page uses.

3. External — a separate .js file

Best for real projects: keep JS in its own file and link it with <script src="file.js"></script>. Add the defer attribute so it downloads in parallel with the page but still runs only after the HTML is parsed.

<script src="script.js" defer></script>

Why placement matters

The browser reads HTML top to bottom, building the DOM as it goes. When it hits a <script> tag, it stops parsing the HTML, runs the JS immediately, and only then continues down the page.

Two problems follow from that:

1. A script in <head> runs before the <body> exists. If that script tries document.getElementById("var-output"), the element isn't in the DOM yet — it returns null, and calling .innerHTML on it throws an error.

2. A blocking script also delays the page from rendering. The user stares at a blank/half-built page until the script finishes downloading and running.

That's why you have three options, each solving it differently:

<script> right before </body> — simplest fix: by the time the browser reaches it, everything above has already been parsed into the DOM, so the elements it looks up are guaranteed to exist.

<script src="..." defer> in <head> — the modern fix: the browser downloads the file in the background without pausing the parser, and holds off running it until the whole document is parsed. Same safety as the bottom-of-body placement, but the download starts earlier (found sooner, since <head> is read first).

Inline onclick — sidesteps the whole issue: nothing runs until the user actually clicks, by which point the page is fully loaded regardless of where the attribute sits.

Variables

Variables store values so you can reuse and change them later. JavaScript has three ways to declare one: var, let, and const.

var vs let vs const

var is function-scoped and can be redeclared — it's the old way, mostly avoided now.

let is block-scoped and can be reassigned — use this for values that change.

const is block-scoped and cannot be reassigned — use this by default, unless the value needs to change.

Data Types a Variable Can Hold

A variable isn't tied to one type — it can hold a string, number, boolean, array, object, or nothing (null/undefined).

Strings

A string is text, wrapped in single quotes, double quotes, or backticks.

Template Literals (Backticks)

Backticks let you embed variables directly inside a string using ${...}, instead of gluing pieces together with +.

Common String Methods

.length, .toUpperCase(), .toLowerCase(), .slice(), .includes(), and .split() are the ones you'll reach for most.
