Closures

A closure is a function that remembers the variables from the scope it was created in, even after that outer scope has finished running. Every function in JS forms a closure over its surrounding scope — this is just what happens when you actually use it.

The Basic Shape

An outer function returns an inner function. The inner function keeps a live reference to the outer function's variables — it doesn't copy them, it stays connected to them.

              // The basic shape
        function outer() {
            let message = "I was created inside outer()";
            function inner() {
                return message;
            }
            return inner;
        }
        const innerFn = outer(); // outer() has already finished running here
        document.getElementById("basic-output").innerHTML = `
            innerFn() → ${innerFn()} (outer() already returned, but inner() still remembers "message")
        `;

Private State — the counter pattern

count can't be reached or changed from outside makeCounter() — the only way to touch it is through the function that closed over it. This is how JS fakes "private" variables.

            
        // Private state — counter
        function makeCounter() {
            let count = 0;
            return {
                increment: () => ++count,
                decrement: () => --count,
                value: () => count
            };
        }
        const counter = makeCounter();
        counter.increment();
        counter.increment();
        counter.increment();
        counter.decrement();
        document.getElementById("counter-output").innerHTML = `
            after 3x increment(), 1x decrement() → counter.value() = ${counter.value()}

            counter.count directly → ${counter.count} (undefined — it was never exposed)
        `;

Each Call Gets Its Own Closure

Calling the outer function again creates a brand new, separate scope. Two counters don't share state — each one closes over its own independent count.

        // Separate closures per call
        const counterA = makeCounter();
        const counterB = makeCounter();
        counterA.increment();
        counterA.increment();
        counterB.increment();
        document.getElementById("separate-output").innerHTML = `
            counterA: incremented twice → ${counterA.value()}

            counterB: incremented once → ${counterB.value()} (completely separate state)
        `;

Function Factories

A closure can also "lock in" a value passed as an argument, then reuse it every time the returned function is called later.

                / Function factories
        function makeMultiplier(factor) {
            return function(n) {
                return n * factor;
            };
        }
        const double = makeMultiplier(2);
        const triple = makeMultiplier(3);
        document.getElementById("factory-output").innerHTML = `
            double(5) → ${double(5)} (factor locked in as 2)

            triple(5) → ${triple(5)} (factor locked in as 3)
        `;

The Classic Loop Bug — var vs let

var is function-scoped, so all three timeouts share the same i — by the time they run, the loop has already finished and i is 3. let is block-scoped, so each loop iteration gets its own i, and each closure remembers its own value.

                // The loop bug
        let varResults = [];
        let letResults = [];

        for (var i = 0; i < 3; i++) {
            setTimeout(() => varResults.push(`var: i is ${i}`), 0);
        }
        for (let j = 0; j < 3; j++) {
            setTimeout(() => letResults.push(`let: j is ${j}`), 0);
        }
        setTimeout(() => {
            document.getElementById("loop-output").innerHTML = `
                ${varResults.join("
")} (all three see the final value of i)


                ${letResults.join("
")} (each closure kept its own j)
            `;
        }, 10);

Memoization — caching with a closure

The cache object lives in the outer scope, hidden from anything outside. The returned function checks the cache before doing expensive work again.

                 // Memoization
        function makeMemoizedSquare() {
            const cache = {};
            return function(n) {
                if (n in cache) {
                    return `${cache[n]} (from cache)`;
                }
                const result = n * n;
                cache[n] = result;
                return `${result} (calculated)`;
            };
        }
        const memoSquare = makeMemoizedSquare();
        document.getElementById("memo-output").innerHTML = `
            memoSquare(4) → ${memoSquare(4)}

            memoSquare(4) → ${memoSquare(4)}

            memoSquare(5) → ${memoSquare(5)}
        `;

Module Pattern

An IIFE that returns an object exposes only chosen methods, while variables declared inside stay private. This is how JS built "public API, private internals" before class and modules existed.

            // Module pattern
        const bankAccount = (function() {
            let balance = 100; // private — no way to reach this from outside

            return {
                deposit(amount) {
                    balance += amount;
                    return balance;
                },
                withdraw(amount) {
                    if (amount > balance) return "insufficient funds";
                    balance -= amount;
                    return balance;
                },
                getBalance() {
                    return balance;
                }
            };
        })();
        document.getElementById("module-output").innerHTML = `
            starting balance → ${bankAccount.getBalance()}

            deposit(50) → ${bankAccount.deposit(50)}

            withdraw(30) → ${bankAccount.withdraw(30)}

            bankAccount.balance directly → ${bankAccount.balance} (undefined — stays private)
        `;
